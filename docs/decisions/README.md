# decisions/

설계 결정 로그. ADR(Architecture Decision Record)의 경량 버전.

## 왜 쓰는가

세 가지를 동시에 해결한다.

1. **학습 기록** — AI가 짠 코드를 설명할 수 있게 만드는 장치
2. **설계 근거** — 몇 주 뒤의 내가 "왜 이렇게 했지"를 다시 묻지 않게
3. **포트폴리오 원재료** — "문제 → 접근 → 결과" 서사가 여기서 그대로 나온다

## 규칙

- 파일명: `NNN-짧은-제목.md` (001부터 순번)
- **3문장은 반드시 개발자 본인이 쓴다.** AI에게 대신 쓰게 하면 이 폴더의 존재 이유가 사라진다
- 3문장을 못 쓰면 그 작업은 끝나지 않은 것이다
- 짧아도 된다. 한 항목에 3~5분이면 충분하다
- 틀려도 된다. 나중에 알게 되면 새 항목을 추가해 갱신한다

## 무엇을 기록하나

선택지가 둘 이상이었던 모든 지점.

- 라이브러리·프레임워크 선택
- 스키마 설계 (컬럼을 나눌지 합칠지)
- API 응답 모양
- 데이터 범위·필터 조건
- 제외하기로 한 것과 그 사유
- 막혔다가 푼 문제
