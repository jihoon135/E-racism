## Phase 1 — 로컬 관통

> **목표는 “완성”이 아니라 “연결”이다.** 데이터 → DB → API → 화면이 한 줄로 흐르는지만 본다.

### 1-1. 레포 뼈대
```
equalizer/
├── apps/web/            Vite + React + TS
├── apps/api/            Spring Boot (Gradle)
├── data/seed/           ratifications_6treaties.csv, country-alias.json
├── scripts/             ETL
├── docs/decisions/      ← 3문장이 쌓이는 곳
└── docker-compose.yml   postgres + pgvector
```
- `E-racism` 레포 재활용 가능 (빈 CRA 템플릿이므로 밀고 시작)
- `.gitignore`: `data/raw/`, `.env`, 빌드 산출물

### 1-2. DB 기동 + 스키마
- docker-compose 한 줄로 postgres 뜨는 것 확인
- 이 단계 테이블은 **3개뿐**: `country`, `treaty`, `ratification`
- `document` / `document_embedding`은 **만들지 않는다** (Phase 5)
- 📌 **스키마 수정 확정**: 명세 §4의 `date_in_force` 하나 → 실제 날짜 4종으로 교체

```sql
ratification(
  iso3, treaty_code,
  status,                      -- STATE_PARTY | SIGNATORY | NO_ACTION
  date_signature,
  date_ratification,
  date_individual_communications,   -- 개인 진정 가능 여부
  date_inquiry_procedure,           -- CEDAW/CRC/CRPD만 존재
  PRIMARY KEY(iso3, treaty_code)
)
treaty(code, name_en, name_ko, data_updated_at)  -- 조약별 갱신일 ← UI 표시용
```

### 1-3. ETL 1~3단계 (fetch / normalize / filter) ✅ 완료
> 실측: treaty 6 / country 197 / ratification 1182. 고유 국가명 198개 = 자동 167 + alias 30 + 제외 1(EU), 실패 0.

- 임베딩 안 함. CSV → ISO3 매핑 → DB 적재까지만
- **국가명 → ISO3**: 자동 매핑 후 실패분만 `country-alias.json` 수작업
- `European Union`만 제외, `Cook Islands`·`Niue`는 적재(사용자 결정 2026-10-26)
- 매칭 실패 건은 삼키지 말고 **로그 출력 + 개수 집계**
- Load는 **upsert** (두 번 돌려도 중복 없게)

> 🔸 **본인 결정**: `State of Palestine`·`Holy See`를 포함할지. GeoJSON에 있는지부터 확인하고 정하되, 어느 쪽이든 `docs/decisions/`에 사유를 남긴다. 정치적 판단이 아니라 **데이터 가용성 판단**으로 적을 것.
> → 결정됨(2026-10-26): PSE·VAT 포함, 데이터 가용성 판단(world-atlas 50m 에 도형 있음, 지도 표시는 1-5 에서 결정). `docs/decisions/` 기록은 본인 작성 예정.

### 1-4. API 엔드포인트 1개
```
GET /api/treaties/{code}/ratifications
→ [{ iso3, status, dateRatification }, ...]
```
> 🔸 **본인 결정**: 응답에 날짜를 전부 실을지, 지구본에 필요한 것만 실을지. 지금은 후자가 맞지만 **왜 그런지**를 답할 수 있어야 한다. (힌트: 지구본은 198개를 한 번에 받는다)

### 1-5. 지구본 색칠
- `react-globe.gl` + `world-atlas` GeoJSON
- ISO3로 조인 → status 3단계 색
- 사실 기록: world-atlas의 id는 ISO3가 아니라 ISO 3166-1 numeric(예: "410")이라 numeric→ISO3 변환이 필요하다. 변환 방법은 1-5에서 정한다.
- **ICERD 하드코딩**. 조약 선택 UI 없음
- 조인 실패 국가는 회색 + 콘솔 경고

### ✅ 완료 기준
로컬에서 `docker compose up` → 백엔드 실행 → `npm run dev` → **브라우저에 ICERD 비준 현황이 3색으로 칠해진 지구본이 뜬다.**

### ❌ 이 Phase에서 하지 않을 것
조약 선택 드롭다운 · 국가 클릭 · 사이드 패널 · 디자인 · 로딩 스피너 · 테스트 · RAG · 나머지 5개 조약

## Phase 2 — 배포 뚫기

> 작동하는 게 생긴 **직후** 뚫는다. 미루면 마감 직전에 CORS·환경변수·콜드스타트와 동시에 싸운다.

### 작업
1. Supabase 프로젝트 생성 → 스키마 적용 → 시드 적재
2. 백엔드: Dockerfile(멀티스테이지) → Railway/Fly/Render 중 1곳 배포
3. 프론트: Vercel, Root Directory `apps/web`
4. **환경변수 3종 분리**: 로컬 / 백엔드 호스트 / Vercel
5. **CORS** — 여기서 반드시 한 번 막힌다. 정상이다
6. GitHub Actions: push → 자동 배포

### 역할
- **위임**: Dockerfile, CI 워크플로, CORS 설정 코드
- **본인**: 계정 생성, 대시보드 설정, 환경변수 주입, **무료 티어 콜드스타트 정책 확인**

### ✅ 완료 기준
**폰으로 URL 열어서 지구본이 뜬다.** (PC 브라우저 캐시에 속지 않으려면 반드시 폰)

### 📌 콜드스타트
무료 플랜은 유휴 시 컨테이너를 재운다. 첫 요청에 JVM 부팅까지 겹치면 수십 초. **포폴 링크를 누른 면접관이 로딩만 보다 나가는 상황**이라 실제 문제다. 대응은 Phase 6에서(헬스체크 핑 / 프론트에 안내 문구 / 유료 전환).

## Phase 3 — 디자인

> 이제 데이터 모양을 안다. 그래서 지금 그린다.

### 정할 것
- 비준 상태 3색 — **색맹 안전성 확인 필수.** 빨강/초록 조합 금지
- 사이드 패널 레이아웃 (아직 안 만들지만 모양은 정함)
- 타이포, 다크/라이트
- **“자료 없음” 상태의 생김새** ← 가장 공들일 화면
- **조약별 갱신일 표시 위치** — CEDAW·CRC가 2023년이라는 사실을 숨기지 않는다

### 📌 왜 “자료 없음”이 제일 중요한가
이 프로젝트의 정체성은 “근거 없으면 정직하게 없다고 한다”이다. 그 원칙이 **눈에 보이는 유일한 화면**이 빈 상태다. 보통 마지막에 대충 처리하는 걸 가장 먼저 설계하는 것 — 면접에서 스크린샷 한 장으로 설명되는 지점.

### 📌 도구
Claude Design의 Design 타입으로 시안을 만들 수 있다. 단 **디자인 규칙을 먼저 주어야 한다**(통합문서 §10). 방향 없이 던지면 평균값이 나온다.

### ✅ 완료 기준
시안이 있고, 색·간격·폰트가 토큰으로 정의돼 있다.

## Phase 4 — 기능 채우기

### 작업
1. 조약 6개로 확장 — 데이터 추가일 뿐, 난이도 안 오름
2. 조약 선택 드롭다운 (**ICRMW를 꼭 넣을 것** — 전환 시 지도가 확 비어서 인터랙션이 눈에 보인다)
3. 국가 클릭 → 사이드 패널: 6개 조약 상태 + 날짜 + 개인통보 수락 여부
4. 로딩 / 에러 / 빈 상태
5. 조약별 갱신일 표시

> 🔸 **본인 결정**: 상태 관리 구조. 선택된 조약·선택된 국가를 Zustand에 둘지 URL에 둘지. (힌트: URL에 있으면 공유 가능한 링크가 된다)

### 📌 개인통보 수락을 따로 보여줄 것
ICERD는 182개국이 비준했지만 59개국만 개인 진정을 받아들였다. ICRMW는 60개국 중 4개국. **“가입했다”와 “개인이 실제로 구제받을 수 있다”는 다르다** — 이 프로젝트가 단순 비준 지도가 아닌 이유다.

### ✅ 완료 기준
조약 6개를 전환하고 국가를 클릭해 상세를 볼 수 있다. 배포돼 있다.

## Phase 5 — RAG

> 여기부터가 차별화 구간. 앞의 4개 Phase는 이걸 올려놓을 바닥이었다.

### 5-1. UHRI 적재
- JSON 다운로드 → 크기·필드 확인
- **필터링 필수** (26만 건 전량 임베딩 금지)
  ```
  mechanism = Treaty Bodies
  theme     ∈ {차별, 인종, 소수자, 이주, 장애, 젠더, 아동}
  year      >= 2015
  → 목표 수천~1만 건
  ```
- 청킹: 권고 1건 = 1청크 (이미 짧아 추가 분할 불필요할 가능성 높음)
- 임베딩 → pgvector (HNSW 인덱스)

> 🔸 **본인 결정**: 필터 조건. 좁히면 정밀도가 오르고 넓히면 커버리지가 오른다. **몇 건이 적정인지 실측하고 정한다.**

### 5-2. “자료 없음” 경로를 먼저 만든다
**정상 답변보다 먼저.** 순서를 뒤집으면 환각 방지가 아키텍처가 아니라 사후 패치가 된다. 면접에서 이 차이를 묻는다.
- 검색 결과 0건 또는 유사도 임계치 미달 → LLM 호출 없이 “자료 없음” 반환
- 🔸 **본인 결정**: 임계치 값. 실제 질문 몇 개로 튜닝하고 **왜 그 값인지** 기록.

### 5-3. 검색 + 생성
- Spring AI `PgVectorStore` + 메타데이터 필터(iso3, theme, year) + 벡터 유사도 = **하이브리드 검색**
- RAG Advisor로 파이프라인 구성
- 프롬프트: “주어진 문서 안에서만 답하라. 근거 없으면 자료 없음.”
- 응답에 **인용 문서 + 원문 링크** 필수

### 📌 표기 원칙 (검증 보고서 §4)
- 테마 태깅은 **기계학습 자동 분류**다. 필터링에는 쓰되 “UN이 이렇게 분류했다”고 표시하면 과장
- 최종견해는 **독립 전문가 위원회의 견해**다. “유엔이 한국을 지적했다” ❌ / “CERD 위원회가 2023년 심의에서 지적했다” ⭕

### ✅ 완료 기준
국가+조약 맥락에서 질문 → 인용 달린 답변, 또는 정직한 “자료 없음”.

| 1 | 레포 뼈대, compose, ETL 구현, 보일러플레이트 | API 응답 모양, 제외 국가 판단 |
